# SF6 ファイターカルテ

ストリートファイター6 の「過去100戦平均のバトルの傾向」を手入力で記録し、
ルールベースで簡単な診断を出す、オリジナル・マイリスト作成アプリ。

## テーマ

対戦相手や自分のプレイデータ（公式サイト Buckler's Boot Camp で見られる
「過去100戦平均のバトルの傾向」）を手入力で記録していくマイリスト。
数値を登録すると、その選手のクセを自動でコメントしてくれる。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `app.py` | ルーティング（View）。SQL は書かない |
| `fighter.py` | `Fighter` クラス。DB の1行を保持するデータクラス |
| `fighter_dao.py` | `FighterDAO` クラス。SQL はすべてここに集約 |
| `validator.py` | `FighterValidator` クラス。入力値チェック |
| `diagnosis.py` | `Diagnosis` クラス。ルールベースの診断 |
| `init_db.py` | DB 構築用スクリプト（最初に1回だけ実行する） |
| `schema.sql` | テーブル定義（提出物②） |
| `seed.sql` | デモデータ 20件 |
| `templates/` | 画面（Jinja2） |
| `static/css/style.css` | CSS（手書き。フレームワーク不使用） |

## 起動手順

```
cd kadai5

# Flask が未インストールなら
py -m pip install flask

# 1回目だけ: データベースを作る
py init_db.py

# 起動
py app.py
```

ブラウザで <http://localhost:5005> を開く。

- `fighters.db` は自動生成される（Git 管理外）。
- データを作り直したいときは `py init_db.py` をもう一度実行する。

## 画面

| URL | 内容 |
| --- | --- |
| `/` | 一覧画面。カードに診断の要約を表示 |
| `/fighter/<id>` | 詳細画面。CSS だけの横棒グラフと診断結果 |
| `/fighter/new` | 新規登録フォーム |
| `/fighter/<id>/edit` | 編集フォーム |
| `/fighter/<id>/delete` | 削除（POST のみ） |

## 工夫した点

### 入力値チェック

チェックはすべて Python 側（`validator.py`）で行い、JavaScript は使っていない。

| 種類 | 対象 | 内容 |
| --- | --- | --- |
| 必須チェック | プレイヤー名、使用キャラ | 未入力ならエラー |
| 正規表現 | CFNコード | `^[0-9]{10}$` 半角数字ちょうど10桁 |
| 正規表現 | ドライブゲージ% | `^[0-9]{1,3}(\.[0-9]{1,2})?$` 小数第2位まで |
| 正規表現 | 回数・秒 | `^[0-9]{1,2}(\.[0-9])?$` 小数第1位まで |
| ホワイトリスト | 使用キャラ、ランク | `select` の選択肢を改ざんして送信されても弾く |
| 相関チェック | ドライブゲージ7項目 | 合計が約100%になるか |

いちばん工夫したのが相関チェック。ドライブゲージの使用実績7項目は、
1項目ずつは 0〜100 の正しい数値でも、合計が 100% にならなければ
どこかで入力ミスをしている。項目をまたいで検証しているので、
1項目ずつしか見ないチェックでは見つけられないミスを拾える。
（公式サイトの表示が四捨五入されているため、99.0〜101.0 を正しいとみなす）

`\d` ではなく `[0-9]` を使っているのは、`\d` が全角数字（１２３）にも
マッチしてしまい、全角のまま DB に入ってしまうため。半角だけに限定している。

エラーになったときはリダイレクトせず、入力した内容を残したまま
フォームに戻し、エラーになった項目を赤くしてメッセージを表示する。

### クラス分け

役割ごとにクラスを分けて、1つのファイルが1つの仕事だけをするようにした。

- `Fighter` … データを保持するだけのクラス。プロパティ（ゲッター）で
  グラフ用のデータを返す。
- `FighterDAO` … SQL を実行するクラス。SQL はこのファイルだけに書く。
- `FighterValidator` … 入力チェックのクラス。チェック項目ごとに
  プライベートメソッドに分けている。
- `Diagnosis` … 診断のクラス。ルールを1つ増やすときは `if` を1つ足すだけ。

`app.py` は「受け取って、呼んで、返す」だけになるので、後から
SQL や診断ルールを直したいときに探す場所が決まっている。

### 診断機能

登録した数値から、そのプレイヤーのクセをルールベースで判定する。
たとえば投げられた回数が投げた回数の1.5倍を超えていれば
「投げ受けが多い。投げ抜けが課題」と表示する。全5ルール。

### そのほか

- ドライブゲージの使用実績は、`width` に % を入れるだけの
  CSS の横棒グラフにした（JavaScript 不使用）。
- SQL の値は必ずプレースホルダ（`?`）で渡している。
- 削除は POST のみで受け付け、URL を直接開いてもデータが消えないようにした。
- 登録・更新の後はリダイレクトし、再読み込みによる二重登録を防いでいる。
